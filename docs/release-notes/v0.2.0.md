# GFF v0.2.0

This release covers the pull requests merged since v0.1.0. It adds the Capcom service, agent
groups, more kinds of rounds, flight rules, an MCP server registry, agents that read and drive
other panes, a new layout for the app, and diagnostics.

## Breaking or needs action

- **Run `gff-hab install` again after you update.** The service keeps running the old build
  until you do. With Homebrew: `brew upgrade gff`, then `gff-hab install`. Running programs keep
  running: the new hab adopts the old holder, and new panes start on a new holder.
- **The service files changed.** Install rewrites them, so no uninstall is needed.
  - macOS: the logic job's output file is now `logs/hab.stderr` in the state folder, not
    `logs/gff-hab.log`. The old file stays until `gff-hab uninstall`; you can delete it.
  - Linux: each unit now starts its program through `/bin/sh`, which appends its output to a file
    in `logs/` in the state folder, as on macOS.
  - gff-hab writes its own log to `logs/hab.log`, capped at 10 MiB with 3 old files.
- **The opencode hook plugin is gone.** `gff-hab hook -print opencode` no longer exists, and
  opencode 2.x refused the plugin it printed. gff-hab follows opencode through its server
  instead. Delete a plugin file you installed from that command.
- **The Capcom service is opt-in, and its engine is not in this release.** With `[capcom] engine`
  unset, Capcom runs in a pane as before. The engine needs Node.js 18.14 or newer and a build of
  `capcom-engine/` from source.
- **Agents can now read other panes.** At the Balanced and Bypass levels an agent may read every
  pane on the hab; at Safe, only the panes of its own project. To stop it, add
  `"agent.read_panes" = "off"` to the `[settings]` table of the hab's config file. Typing into
  and starting panes is tighter: see "Agents and sessions".
- **Approvals now expire.** `approval.max_age` (default 60 minutes) is now enforced. The app
  cannot answer an older request; answer it in the terminal. For no limit, set it to 0 in the
  app's Settings, or `"approval.max_age" = 0` under `[settings]`.

## Capcom

- The Capcom service: Capcom runs as its own engine on the Claude Agent SDK, with no pane. A
  second engine runs on the Codex SDK (`[capcom] engine = "codex"`).
- The app and `gff` show the Capcom thread: read marks, typing, Stop, approval cards and earlier
  threads from other hosts.
- Capcom manages its own context: summaries, a fresh start past a set size, and memory in the
  Logbook.
- Capcom can write first when an event needs you, within quiet hours and a daily cap.
- Capcom jobs: a Capcom round may act on events, with actions only you grant, from the app.
- A usage governor paces Capcom against your plan's limits. The app shows it, with Send now.
- Personal tools and device context (location, calendar) on iPhone and Mac.

## Agents and sessions

- Agent groups: plan a group, start its members with one confirmation, run a review lane, move a
  group to another host, and let Capcom coordinate it.
- `spawn`: any agent starts a teammate in any harness, on any host, with turn reports over
  channels.
- Agents read and drive other panes, on this host or a peer:
  - Read a pane's screen and scrollback, and wait for a line of output, for quiet or for exit.
  - List panes, type into a pane, and start a new one.
  - From the shell: `gff-hab screen`, `wait`, `panes`, `type` and `new`. As MCP tools:
    `pane_list`, `pane_read`, `pane_wait`, `pane_type` and `pane_new`.
  - `agent.drive_panes` decides who may type and start. Balanced lets an agent type only to the
    other agents of its own project. Safe allows nothing. Bypass allows every pane.
- The hab answers a Claude Code question from the app. See "Known limits".
- `session.restart` restarts an idle agent through its harness's resume, one session at a time.
- Resume refuses a conversation that already runs in a plain terminal.
- The agent kit: session variables in every pane, self-naming, and a check that a skill's CLI
  exists.
- A shell session's name now clashes with a peer's, as an agent's does.

## Rounds

- Event rounds run on this hab's own events, gathered in batches.
- Watch rounds keep a watcher program running and turn its output into events.
- Rounds in the agent kit, and a round on another host behind a confirmation.
- A finished round with `on_finish close` leaves no exited session behind.

## Flight rules and MCP

- Flight rules: a per-session ledger of the context that reached the agent, for Claude Code,
  Codex and opencode, with a flag when a render is stale.
- An MCP server registry in the config file, rendered into Claude Code, Codex and opencode.
  Secrets resolve at launch through a secret provider and never land in a file.

## Terminal client (`gff`)

- Links (OSC 8) stay clickable in the composed view.
- The kitty keyboard protocol works in the composed view.
- Reopen a closed view, a shell after a program exits, and the window title.
- Warnings name a hab that runs an older version, and panes on a holder of another build.
- `gff friction` records a friction note with the recent log.
- `gff group` runs `gff-hab group`, as `gff round` runs `gff-hab round`.
- `gff` no longer warns about the `[instructions]` and `[mcp]` tables. `docs/examples/gff.toml`
  shows a full config.

## Diagnostics

- `gff-hab status` and `gff-hab logs` (merged, followable, filtered by time and process).
- Crash and unclean-stop records, and a line for each failed request.
- Tallies: local usage counts that never leave the host.
- `gff-hab stacks` writes a stack dump. A watchdog logs one line and one dump when gff-hab stops
  answering for 10 seconds.
- `gff-hab debug` turns on debug logging for a set time. The window survives a restart.
- Trace ids: each request from `gff` or the app carries one, and a failed request's log line
  shows it on every hab it reached. `gff-hab logs --trace <id>` shows one action's lines.

## Logbook and modules

- Logbook export and import (JSONL or Markdown), and fixes so replicas always agree after a
  redaction.
- Modules run in a process of their own, and pause after three failures in a row.

## App

The app ships on its own release line. These changes reach you with the next app build.

- A new layout on iPhone and iPad: four tabs, Sessions, Capcom, Rounds and Settings. The Mac
  keeps its board window.
  - Sessions groups work into Needs you, Working, Done and Other. Allow, Deny and Answer sit on
    the row.
  - Settings holds your computers, the level, this device's settings, and help and diagnostics.
  - First run offers four ways in: scan a code, type a code, set up over SSH, or look around with
    demo data.
- The chat view reads better:
  - Tool calls read as sentences, such as "Edited src/api/stations.ts +2 -1".
  - Diffs show a file header and line numbers. Wide diffs and code scroll sideways.
  - "Show in chat" hides kinds of content, for every session or one.
  - Answer from chat: question options as buttons, free text from the composer, and a
    permission's command and folder.
- The terminal view fits the screen:
  - The font follows your text size. Choose Fit to this screen or Host size from the size menu.
  - A key bar under the terminal holds Esc, Tab, Ctrl, Opt, arrows and more. It hides when a
    hardware keyboard is attached.
- Confirmation cards for rounds and group plans.
- Capcom messages show as communication notifications on iPhone.
- The app keeps its own log, `app.log`, without host names or paths.

## Known limits

- **Question answers.** The hab now takes them; the app sends them from its next build. By
  default the hab answers one single-choice question by picking its option on screen. Free text,
  several questions and multiple choice need the waiting hook. Turn on "Answer permissions from
  the app" in the app's Settings for that computer, or set `"hab.permission_wait" = 30` under
  `[settings]` in the hab's config file. Without it, the app asks you to answer in the terminal.
- Codex and opencode send no question requests, so the app cannot answer their questions.
- The Capcom engine is not in this release (see "Breaking or needs action").

## Fixes, security and dependencies

- Go 1.27.4 and `golang.org/x/crypto` 0.59.0, both with security fixes.
- libghostty moves to a newer Ghostty, which fixes a restored terminal's bottom page. Its build
  now fetches its dependencies first, then builds offline.
- The speech helper moves to sherpa-onnx 2.0.2. `NOTICE` lists its new parts.
- `gff-hab events` ends a stream that hears nothing for 45 seconds.
- A stopping gff-hab no longer hands the heavy-run lock to a waiting command. Before, two
  commands could hold it after a restart, and a waiting command could hang on Linux.
- gff-hab now declares every capability it sends.
- Many fixes for timing-dependent tests, and steadier CI.
