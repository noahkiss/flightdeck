# GFF v0.4.0

This release covers the pull requests merged since v0.3.0. Each release archive now carries the
Capcom engine, so an installed hab can run the Capcom service with no source build. The engine
stays off until you turn it on.

## Breaking or needs action

- **The Homebrew formula now depends on Node.js.** `brew upgrade gff` installs `node` if it is
  missing, even when the Capcom service stays off.
- **Run `gff-hab install` again after you update.** The service keeps running the old build
  until you do. With Homebrew: `brew upgrade gff`, then `gff-hab install`. Running programs keep
  running.

## Capcom

- **The engine ships in each archive.** Each archive holds `capcom/`: the engine bundle, its npm
  manifest and lockfile, and a `NOTICE`. The archives do not carry the Claude Agent SDK or the
  Codex SDK: they hold a native binary for each platform, and the Claude Agent SDK's licence does
  not allow redistribution.
- **Turn it on.** Set `engine = "claude"` (or `"codex"`) in the `[capcom]` table of the hab's
  config file, then run `gff-hab install`. Install copies the engine into the hab's state folder
  and runs `npm ci` there. That downloads both SDKs, about 800 MB, so it needs network access and
  Node.js 18.14 or later with npm on PATH.
- **Each upgrade sets up a new engine.** Each release's engine carries its version, so the
  `gff-hab install` after an upgrade runs `npm ci` again. npm's cache usually makes the second
  download quick.
- **A failed setup keeps the previous engine.** When `npm ci` fails or times out (after 10
  minutes), or Node.js is missing, install does not fail. It prints one notice with the cause and
  keeps the engine installed before, if any. The hab logs a warning when the engine's version
  differs from its own; run `gff-hab install` again to fix it.
- **SDK versions.** The Claude Agent SDK is now 0.3.329 and the Codex SDK 0.171.0.
