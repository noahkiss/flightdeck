# GFF v0.5.0

This release covers the pull requests merged since v0.4.0. Capcom no longer makes the owner's
messages wait for usage, and its four pace values become settings that the app can edit.

## Breaking or needs action

- **`pace_wait_at` is no longer used.** A config file that sets it in `[capcom]` still loads.
  gff-hab logs one line that it ignores the key. The owner's messages never wait now: past
  `capcom.pace.small_at` they run on the small model.
- **`daily_usd` no longer caps the owner's messages.** Under `auth = "api_key"`,
  `pace_wait_at = 100` with `daily_usd` was a hard daily cap. After the upgrade it is not.
  `max_turn_usd` bounds each turn, and event turns still stop at `capcom.pace.event_stop` of the
  cap. If you relied on the hard cap, lower `max_turn_usd`.
- **Run `gff-hab install` again after you update.** The service keeps running the old build
  until you do. With Homebrew: `brew upgrade gff`, then `gff-hab install`. Running programs keep
  running.

## Capcom

- **The owner's messages never wait.** A user turn's pace is at most the small model. `gff` and
  the app say when Capcom runs on the small model or holds its own event turns. They never say
  that a message is paused.
- **Four pace settings.** `capcom.pace.daily_share`, `capcom.pace.small_at`,
  `capcom.pace.events` and `capcom.pace.event_stop` are hab-side settings. The app edits them
  under Usage, and a change applies at once, with no restart. `capcom.pace.events` is new: off,
  event turns never wait for usage.
- **Config locks a setting.** A value under `[settings]`, or the older `[capcom]` keys
  `pace_daily_share`, `pace_small_at` and `pace_event_stop`, locks its setting. The app then
  shows the value and cannot change it. When both name one setting, `[settings]` wins.
- **Send now.** The `send_now` flag changes nothing on a current hab, since no user turn waits.
  It still matters for an older hab.
- **SDK version.** The Claude Agent SDK is now 0.3.330.

## Other changes

- Dependency updates: `regexp2` 2.13.1, and pinned action versions in the release workflows.
- The API schema changes only in descriptions (`send_now`, `pace`). The revision stays 1.

## Details

- The pace settings and their ranges: `docs/specs/capcom-service.md` 10.1 and 19.1.
- The `[capcom]` keys and the upgrade note: `docs/specs/capcom-service.md` 19.2.
