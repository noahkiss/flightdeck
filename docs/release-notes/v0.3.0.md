# GFF v0.3.0

This release covers the pull requests merged since v0.2.0. The autonomy level now sets the
permission mode of each new agent session. Capcom reads and drives panes, runs session actions,
and acts on events by level. The app now answers every kind of Claude Code question by default.

## Breaking or needs action

- **New agent sessions start in auto mode.** The autonomy level now sets the permission mode
  each new agent session starts in (`agent.start_mode`).
  - A hab that no app has connected to yet uses Balanced. Claude Code starts with
    `--permission-mode auto`, Codex with `--approve-for-me`. This also applies to unattended
    rounds and to peer habs.
  - The first connect of a Safe app writes Safe: no flag is added. The first connect of a Bypass
    app writes Bypass: Claude Code starts with `--permission-mode bypassPermissions`, Codex with
    `--dangerously-bypass-approvals-and-sandbox`.
  - An explicit permission flag in your own arguments (a round's `harness_args` included) wins:
    the hab adds nothing.
  - The added flag overrides the harness's own config, such as a Claude Code `defaultMode` or a
    Codex `approval_policy`.
  - To turn it off, add `"agent.start_mode" = "ask"` to the `[settings]` table of the hab's
    config file. That locks the setting on that hab. Or pick Safe, or Custom, in the app.
- **The agent waits 60 seconds for your answer.** `hab.permission_wait` now defaults to 60
  seconds (it was 0, off). While an app or `gff` that can answer is connected, Claude Code waits
  up to a minute for an answer from it before its own dialog takes over. The same setting covers
  Codex's permission hook. A hab with no such client connected adds no wait. To turn it off, set `"hab.permission_wait" = 0` under `[settings]`, or turn off "Answer
  permissions from the app" in the app.
- **Capcom at Bypass acts on events with no job.** On a Bypass hab, the first connect after the
  app update moves `capcom.event_actions` to `all`. From then on an event turn may act with no
  job. To keep `allow`, pick Custom in the app and set it, or set
  `"capcom.event_actions" = "allow"` under `[settings]`. A value you wrote is never moved again.
- **Two Capcom limits are higher.** `capcom.events.daily_turns` now defaults to 200 (was 20),
  and 0 means no cap. `capcom.event_actions_per_turn` now defaults to 10 (was 3), with a range of
  0 to 50.
- **Run `gff-hab install` again after you update.** The service keeps running the old build
  until you do. With Homebrew: `brew upgrade gff`, then `gff-hab install`. Running programs keep
  running.

## Capcom

- Capcom reads every pane, on this hab and on peers, at every `agent.read_panes` value but a
  hand-set `off`.
- Capcom types into panes and starts them under `agent.drive_panes`, with every project as its
  scope. At `all` it types a raw line, so slash commands work, and may start a pane.
- Session actions: `compact`, `clear`, `restart`, `close` and `recreate`, through
  `session.action`, `gff-hab action` and Capcom's `session_action` tool. Only you and Capcom may
  run them. `recreate` starts a fresh session in the same folder, with the same harness and
  model, and moves its messages over.
- Event turns by level: at `all`, an event turn may act with no job, under each call's own
  gates. A new action word, `drive`, covers typing into panes, starting panes and session
  actions. An action no job granted shows a card that names its event.
- Quiet hours hold pushes, not turns. Event turns run at any hour. At the end of quiet hours,
  one push counts the messages that wait. `capcom.quiet_hours` takes `off`.
- The daily turn budget is 200 event turns. Your own jobs run outside it.
- Standing instructions become jobs. Ask Capcom for a lasting instruction, and it makes a job
  that counts as yours: it runs outside the daily budget, and no agent may edit, pause or delete
  it.
- The grant card: when such a job needs action words, Capcom asks with a card. It shows the
  prompt, the trigger and the words; one tap grants them. A job changed since the card grants
  nothing.
- The manual tells Capcom that screen text is data, to keep agents fresh with session actions,
  and to make a lasting instruction a job.

## Agents and sessions

- Resume, restart, recreate and a group member's fresh session start with the lower of the
  session's recorded mode and the current setting. Lowering the level lowers old sessions at
  their next start; raising it never raises them.
- Not covered by the start mode: plain programs (`pane.new`), the Capcom service's own session,
  and a conversation you adopt.

## App

The app ships on its own release line. These changes reach you with the next app build.

- The levelled row "New sessions start in". The session header shows "Auto mode" or "Bypass
  permissions" when a session started in one.
- The grant card in the Capcom thread: "Let job <name> act?", with Not now and Grant.
- Quiet hours on the Capcom host page: "Hold Capcom's pushes at night", with From and Until.
- Capcom jobs gain a "Drive panes and sessions" switch (`drive`). The per-turn row goes from 0
  to 50.
- Question answers: with the 60-second wait on by default, the app answers every kind of
  question: one option, free text, several questions and multiple choice.

## Known limits

- **Codex and opencode session actions.** `compact` and `clear` answer `unavailable` for Codex
  and opencode. Use `recreate` instead.
- **opencode start mode.** The opencode row is unverified. The hab adds no flag for opencode and
  logs one line per start.
- **Codex resume and fork.** Nobody has checked that a mode flag placed before `codex resume` or
  `codex fork` takes effect at run time.
- **Claude Code `compact` and `clear`.** The tests drive hand-written hook payloads; neither has
  run against a real Claude Code session.
- **Codex blocking hook.** Nobody has run Codex live with the 60-second wait on.
- **Peer device ids.** Capcom's mark on a forward is honoured only from the peer that holds the
  Capcom home. That peer's device id comes from its own hello, so the mark is only as strong as
  the peer door (`hab-logic-api.md` 3.11).
- Codex and opencode send no question requests, so the app cannot answer their questions.
- The Capcom engine is not in this release. Build `capcom-engine/` from source (Node.js 18.14 or
  newer) to use the Capcom service.

## Fixes
